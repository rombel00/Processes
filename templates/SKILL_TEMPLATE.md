### Если метод — несколько фаз, каждая копит результат

**Пиши черновик на диск после каждой фазы**, а не только в конце:
`.process/<артефакт>_draft.md` (класс `scratch`). Вернувшись, продолжай с него.

Иначе всё, что накоплено вопросами и ответами, живёт только в истории диалога:
владелец закрыл сессию на середине интервью — и восстанавливать нечего, потому
что артефакта ещё нет. Это прямо ломает главное свойство системы — работа
восстановима из файлов, а не из разговора.

### Если это доменный пак (замещает другой скилл)

`replaces: <имя скилла>` во frontmatter — для Claude Code не значит ничего,
он выбирает по `description`, не по frontmatter (`ARCHITECTURE.md` §1). Значит,
правка обязательно **парная**, одним коммитом: в `description` **этого**
скилла — что он замещает и для какого домена; в `description`
**замещаемого** скилла — что для этого домена есть замена и он сам не
годится. Односторонняя правка означает, что замещаемый скилл продолжает
матчиться на домен, для которого не подходит, и молча выигрывает выбор —
это уже находили и чинили один раз, второй раз находить дороже.

## Результат

**Назови свой гейт и предложи его запустить.** Если `gate:` во frontmatter не
`null` и выбранная глубина процесса его требует (`PROCESS.md`, «Что означает
глубина для всего трека») — скажи владельцу, какой гейт у этого артефакта
(имя ревьюера бери из таблицы «Гейты» в `PROCESS.md`, не храни его у себя —
`PROCESS.md`, «Правила движения» п.3), и предложи запустить ревью.
Если глубина гейт не требует — так и скажи, не молчи о нём. Владелец
согласился сразу — организуй ревью сам (субагент, чистый контекст, другая
модель) и запиши результат сам: отметку в `status.md`, принятый долг — в
свой артефакт (там же, п.3, тот же раздел «правил движения»). Не жди для
этого будущего вызова `orchestrate`.

**Правишь committed-артефакт задним числом** (не первая запись, а правка уже
принятого) — отметь в «Открытые вопросы» `status.md`, что построено поверх
старой версии и не пересмотрено (`PROCESS.md`, «Правила движения» п.7).

**Запись на диск общая для интерактивного и автономного режима, если они у
скилла оба есть.** Не переноси инструкцию «запиши на диск» внутрь описания
только одного из режимов — шесть скиллов волн 1–2 уже наступили на эту
грабли: интервью заканчивалось словами «выдай чистовую версию» без записи
файла, и работа целого диалога оставалась только в истории чата.

Запиши артефакт в `<путь>`.

**JSON-конверт — не общий**, вопреки записи на диск (`ARCHITECTURE.md` §6):
в диалоге с владельцем он не нужен, файл на диске уже и есть результат, а
прозу читает человек, не парсер — просто скажи, что и куда записано. Конверт
обязателен только там, где ответ читает не человек: автономный/пайплайн-режим
(передаёт оркестратору) и ответ ревьюера (у него интерактивного режима нет
вовсе).

```json
{
  "status": "done",
  "artifacts": ["<путь>"],
  "assumptions": [],
  "blocking_questions": []
}
```

Если завис вопрос класса Б (`PROCESS.md`, «Блокеры и эскалация») — артефакт
всё равно пишется на диск как есть, но статус другой, и работа сама
останавливается, не дожидаясь, что это поймает ревьюер (в диалоге — скажи
это прозой форматом остановки, конверт не заменяет её):

```json
{
  "status": "blocked",
  "artifacts": ["<путь>"],
  "assumptions": [],
  "blocking_questions": ["<вопрос>"]
}
```
