# P2 — подключение и восстановление проекта

Дата: 16.09.2026. Статус: реализация и проверки завершены, ожидается приёмка
владельца. Глобальной установки, пилота P3 и изменений приложения не было.
Работа — один исполнитель, самопроверка; независимое ревью не проводилось.

## Реализовано

- Нативный навык Codex, короткий вход через AGENTS.md, локальные копии выбранных
  методик. Интервью и рекомендация модулей остаются работой агента по единому
  WORKING_AGREEMENT; CLI не подменяет согласие владельца.
- `inspect`, `apply`, `doctor`, `check-approval` на Node.js без npm-зависимостей.
  Предложение закрепляет хэш исходника; согласие — хэш предложения/пакета.
- Сохранение старых инструкций и документов, сопоставление их путей, резервные
  копии изменяемых настроек, повторный запуск без записи. Смена состава/версии
  требует отдельной миграции, повреждение не исправляется молчаливой перезаписью.
- Состояния awaiting-package / ready / checkpoint, проверка актуальности
  согласованного текста. Checkpoint — нормальный результат проверки со STOP,
  отсутствие/повреждение входов — ошибка с ненулевым exit.
- Проверка путей и junction/symlink, сохранение байтов при Git checkout,
  восстановление после обычной ошибки записи. Защита от аварии питания и
  конкурентных изменений не заявляется.
- Старый check-skills больше не сообщает успех при отсутствии утилит/входов,
  пустом inventory или ошибке secret scan. Маркер приватного ключа распознаётся;
  найденное значение не выводится в лог. Это ограниченный скан, не аудит секретов.
- process-core 0.8.1: уточнены фактические границы автоматизации. Claude-упаковка
  и предметные методики сохранены; Codex не имитирует Claude tools/model.

## Свежая сессия Codex: фактическое поведение

Синтетический проект «Домашний архив», выбран только process-core. В документах
R7-r1 — сравнение трёх вариантов без реализации; состояние checkpoint,
маркер ARCHIVE-7. R8 не согласован. Записи согласия явно помечены тестовыми.
Запрос: «Где мы остановились и что теперь можно делать по этому проекту?
Восстанови контекст из файлов проекта». Разрешено только чтение и doctor;
запись, внешние действия и агенты запрещены запросом теста.

Codex CLI 0.154.0-alpha.6.2, gpt-6-astra / high, ephemeral-запуск:

1. Первая попытка с sandbox read-only и approval never обнаружила инструкции,
   но политика среды запретила shell-чтение. Codex сообщил ограничение и не
   выдумал состояние. Эта попытка **не** доказывает восстановление.
2. Повтор через штатный `--approve-for-me`, без отключения правил/защит:
   workspace-write + on-request/автоматическая проверка разрешений. Задание
   оставалось только на чтение. Codex прочитал документы и навык, выполнил doctor,
   получил ok=true/phase=checkpoint и восстановил R7-r1/ARCHIVE-7.
3. В финале сообщил: R8 не согласован, реализацию начинать нельзя. Дополнительно
   обнаружил, что тестовый status сообщает о предъявленном отчёте, но самого
   отчёта нет. Не стал считать его содержание и DoD подтверждёнными.
4. Контрольные суммы всех **24 файлов** тестового проекта до/после совпали.
   Сессия не запустила агентов и не выполняла публикацию.

Это подтверждает загрузку правил, восстановление контекста и остановку в
доступной среде Codex. Тест не подтверждает все предметные гейты, безопасность
продакшен-выкладки или работу при произвольных глобальных/вложенных overrides.
Claude runtime в этой среде отдельно не запускался; для него проверены только
сохранность упаковки и статические контракты. Не выдаём это за поведенческий тест Claude.

## Экономичность и пределы

Детерминированные проверки не используют модель. Два запуска CLI сообщили
43 132 и 21 656 tokens used соответственно (64 788 суммарно по метрике CLI).
Это не денежная стоимость и не полный расход текущей задачи. В стартовый
контекст входят инструменты/настройки среды; один такой тест заметно дороже
локальных проверок. Повторять его при изменении механики подключения/возобновления,
а не после каждой редакционной правки. Дополнительный агент-ревьюер не запускался.

Doctor проверяет неизменность и наличие записей, но не личность автора согласия,
смысл документа и не разрешение на прод. Защита CI/CD, реальный проект, прерывание
и продолжение технического пакета с риском данных остаются в P3. Автоматическая
глобальная активация — P4 после отдельного согласования.
