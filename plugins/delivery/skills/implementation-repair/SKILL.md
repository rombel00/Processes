# Implementation Repair — точечное исправление

До исполнения прочитай [общий договор](../../../process-core/WORKING_AGREEMENT.md),
«Правила движения» PROCESS, отчёт `code-review`, `plan` и `test_report`. Rework
разрешает исправить перечисленные находки, но не менять
продуктовую логику, архитектуру или границы пакета.

Основной путь — субагент `implementation-repair`, вызываемый после единственного
содержательного `code-review`. Ты не ведёшь и не запрашиваешь повторное
независимое ревью.

## Правила

1. Прочитай отчёт целиком и преврати каждую 🔴/обязательную находку в явный
   пункт проверки.
2. Исправляй только названные места. Попутное улучшение вынеси отдельно.
3. Недостающее живое доказательство не заменяй ещё одним mock/stub.
4. Для каждой находки запусти адресный тест или другую наблюдаемую проверку.
5. После всех правок один раз прогони финальный regression.
6. Обнови актуальные разделы `test_report`: покрытие, изменённые файлы,
   визуальные доказательства и статус code review.
7. Закоммить починку поверх финального кандидата, не переписывая историю.

Если находка требует новой архитектуры, изменения scope или починка стала
настолько широкой, что её нельзя надёжно сверить по diff и тестам, верни
`blocked`. Правильное действие — уменьшить подблок или согласовать новый пакет,
а не покупать уверенность вторым reviewer-вызовом.

## Отчёт о починке

Пиши `.process/<task-id>/implementation_repair.md`:

```markdown
# Repair Report: implementation

## Закрытые замечания
| Находка | Изменение | Доказательство | Статус |
|---|---|---|---|

## Осталось нерешённым
- …

## Изменённые файлы
- …

## Финальный regression
[команда и результат]
```

## Результат

```json
{
  "status": "done",
  "artifacts": ["<путь test_report>", ".process/<task-id>/implementation_repair.md"],
  "resolved_findings": ["<id находки>"],
  "repair_commit": "<hash после починки>",
  "verification": ["<адресная проверка>", "<финальный regression>"],
  "next_step": "Основная задача сверяет каждую находку с diff и доказательством, фиксирует итоговый commit и закрывает подблок без второго code-reviewer.",
  "assumptions": [],
  "blocking_questions": []
}
```

Осталось критичное или нужна развилка владельца — `status: "blocked"`.
