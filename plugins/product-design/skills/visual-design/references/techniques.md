# Технические практики visual-design

Снимают конкретные, повторяющиеся баги — не общие рекомендации, каждый
пункт из реальной практики (`rombel00/pair_anal`, `docs/design/`).

## Самодостаточные прототипы

HTML+CSS без сборки, по файлу на экран или тесную группу экранов, общие
CSS-токены (`:root`) дублируются в каждом файле намеренно — открывается
прямо в браузере, без сети и без стадии сборки.

## Шрифт: скачать `.woff2`, проверить кириллицу, зашить base64

Обязательно **до** показа владельцу любого шрифта-кандидата:

```
curl -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Safari/537.36" \
  "https://fonts.googleapis.com/css2?family=<Font+Name>" | grep cyrillic
```

Несколько популярных «дизайнерских» шрифтов (Fraunces, Work Sans,
Quicksand, Karla — не исчерпывающий список) вообще не имеют кириллических
глифов и молча падают на системный шрифт — на глаз в браузере с рабочей
сетью это не поймать. Зашивать как `data:font/woff2;base64,...` —
офлайн-прототип не может полагаться на живой CDN шрифта.

## Иконки — CSS-фигуры, не текстовые глифы/эмодзи

Юникод-символы (стрелки, сердечки, чекбоксы) садятся на разную высоту в
разных шрифтах и на глаз выглядят «чуть не так» — источник самого частого
класса повторных правок. Рисовать псевдоэлементами (`border` для
шевронов, повёрнутые прямоугольники для сердец и плюс/минус) — не зависит
от шрифта. Жёсткий запрет на эмодзи как визуальный язык вообще.

## Интерактивность без JS

`<input type="checkbox">` + `:checked ~ .sibling` — рабочее
раскрытие/сворачивание в статическом прототипе без единой строки JS.
Использовать везде, где состояние бинарное (раскрыть описание, показать
доп. поля).

## Проверка скриншотом — по-настоящему, не на словах

Playwright, реальный вьюпорт устройства (390×844, `deviceScaleFactor: 2`),
дождаться `document.fonts.ready`.

**Ловушка `fixed`-навбара.** Если контент выше вьюпорта, а внизу есть
`position: fixed` навбар — обычный `fullPage: true` скриншот кладёт
навбар поверх контента, который на реальном скролле до него не
дотягивается (Chromium в этом режиме привязывает `fixed`-элемент к высоте
*исходного*, не полного вьюпорта). Чинить либо замером `scrollHeight` и
ресайзом вьюпорта под него перед снимком, либо не доверять скриншоту и
проверять математику отступа (`padding-bottom` контейнера ≥ высоте
навбара) напрямую.

## Контраст — по формуле, не на глаз

WCAG AA (≥4.5:1 текст, ≥3:1 рамки) считать luminance-скриптом на каждую
пару текст/фон при выборе палитры, не полагаться на субъективное «вроде
читается». По той же причине — «фон стал чуть светлее» на глаз может быть
иллюзией: если просят «светлее», считать реальную дельту luminance, а не
смещать hex наугад.

## Частые грабли — чек-лист

- Смена направления «поднимает/понижает» на CSS-нарисованный треугольник
  незаметно превращается в заливной треугольник вместо тонкого шеврона —
  форма символа тоже часть утверждённого решения, не только его наличие.
- Попап/шторка, позиционированные `left: Npx` вручную под один набор
  кнопок, разъезжаются при следующем изменении состава этих кнопок —
  пересчитывать при каждом изменении соседей, не оставлять на глаз.
- `<a class="button">` без `display: inline-flex` — `min-height` и
  центрирование по кросс-оси не применяются к строчному элементу; кнопка
  выглядит смещённой без единой ошибки в логике разметки.
- Просьбу про одно состояние экрана легко привязать не к тому экрану, если
  в диалоге упоминались оба подряд — переспрашивать при малейшей
  двусмысленности, дешевле, чем чинить не то.
- «Причесать» формулировку при технической правке (например, слить
  подписанные подзаголовки в текст, хотя просили только добавить
  сворачивание) — то же нарушение «не трогай, что не просили», просто
  замаскированное под «заодно улучшил».

## Внешние источники методики

- **Anthropic, скилл `frontend-design`** — дисциплина триады токенов,
  «один акцентный приём, не пять», сознательное избегание типового
  «AI slop».
- **Impeccable** — классификация режимов интерфейса (Operate+Read против
  Persuade+Experience) и прикладные правила контраста — чек-лист при
  выборе, насколько сдержанным должен быть конкретный экран.
- **Emil Kowalski, скилл по моушену** — если экранам эпика нужны
  транзишены/микроанимации (по умолчанию прототипы статические).
- **Vercel, `web-design-guidelines`** — общий чек-лист паттернов
  веб-интерфейса, second-opinion перед показом владельцу.
